# 26.10.1 — run the container as the host user on Linux

## What changed

- **`McpServerFixture`** adds `--user <uid>:<gid>` (read with `id -u` / `id -g`) to `docker run` when
  the tests run on Linux. `docker-scripts/smoke_session.py` does the same.
- **how-to/02** gains *Linux: run as your user* and a troubleshooting row for
  *"The index folder … is not writable"*.
- Version pins moved to **26.10.1** (`Directory.Build.props`, `integration.yml` defaults, examples,
  how-to guides, docker-scripts).

## Why

The first CI run against the published 26.10.0 image failed 20 of 31 tests on `ubuntu-latest` with
`UnauthorizedAccessException: Access to the path '/data/.groupdocs-search-index' is denied`. The image
runs as uid 1654; on a Linux host the bind-mounted temp folder keeps the runner's ownership, so the
container user cannot create the index. The 11 tests that passed were the ones that never write.
Docker Desktop on Windows does not enforce bind-mount ownership, which is why the local runs passed.

The fixture now launches the container the way the README tells Linux users to, so the suite tests the
documented configuration. The server side (26.10.1) turns the same failure into a message that names
the fix.

## Migration impact

None. Windows and macOS runs are unchanged.
